# 三场景启动接口验证

本次验证范围是 x86 主机上的 CARLA 0.9.16 启动、传感器输入、模型加载、车辆控制和独立评测连接，不是三个场景全程通过。实测使用 RTX 5090 加速，不是纯 CPU 性能测试，也不是 J6P 性能测试。

## 修改内容

- 场景一入口显式启用 `--bind-task-geometry`。原固定出生点、左转里程和换道准备区间不能同时通过 Town04_Opt 地图检查；新接口搜索实际地图，并选择任务里程改变量较小的有效布局。
- 保留 5 公里路线、15 条指令、指令内容、原激活先后顺序、目标速度、500 米换道准备区间及全部原验收阈值。只重绑定出生位置和任务里程，不跳过路线检查。
- 将绑定结果保存为运行目录内的 `scenario_config.map_bound.json`，同时记录原配置校验值、地图校验值、距离映射和路线检查证据。控制器与独立评测读取同一份配置。
- 独立评测校验来源配置、实际地图和指令语义；评测模板只同步绝对路线位置，速度容差、保持时间、安全阈值和超时预算保持不变。禁止借配置绑定改变任务要求。
- 场景二统一入口显式传递 `--external-ego-control`。
- 有界诊断入口不再强制传递场景二的 `--competition-run`，但继续启用独立 `--benchmark-assessment`；短时运行不冒充正式竞赛全程运行。子进程显式获得项目导入路径。
- 统一入口区分启动失败、评测不完整、评测失败。保留原非零评测退出码，不把短时测试包装成完整通过。

绑定后的场景一是新的地图适配布局，不能标注为原固定里程场景的同条件复现。原配置文件没有被覆盖。几何绑定仅用于测试场景构建，不向模型提供事件答案或动态对象真值。

## 运行入口

在项目根目录和已配置的模型环境中启动 CARLA 服务后执行。每次使用新的输出目录：

```bash
python experiment/CARLA/tools/run_challenge_x86.py \
  --scene scene1 \
  --model-root /root/autodl-tmp/models/challenge-assets-pinned \
  --device cuda \
  --duration-s 20 \
  --output /root/autodl-tmp/review_logs/scene1_startup_new \
  --execute
```

另两个场景将 `--scene` 改为 `scene2` 或 `scene3`，并修改输出目录。此统一入口默认保留传感器记录，磁盘占用高于本次关闭原始落盘的短时诊断。

查看 `preflight.json` 中的 `closed_loop_started`、`valid_control_frames`、`status` 和 `runner_exit_code`。`assessment_incomplete` 或 `assessment_failed` 表示已运行但未通过评测，不等于程序无法启动。任务完成情况以 `run/benchmark/summary.json` 为准。
