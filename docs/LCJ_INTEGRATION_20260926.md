# LCJ 语音模块更新整合

整合来源：`lcj-challenge-track` 的 `2752e52`。此前 `c48f4bb` 的语音目录已纳入公共分支，本次只应用新增提交，不恢复其旧公共文档或覆盖其他成员代码。

## 本次变化

- 优化前处理失败或结果为空时，可回退到原始音频，并输出 `optimization_fallback`。
- 补充 `asr_success`、`translation_success`，增加后端配置及调用适配。
- 默认后端仍是 PyTorch；预加重与方言归一默认关闭，属于有意的行为配置变化，历史精度不能直接当作新默认值的成绩。
- 保留新 J6P 编译及运行代码，但本次不启动工具链、不转换模型、不验证板端 API。
- 解决新增延迟导出与公共包导入冲突，新增后端使用相对导入，保留从仓库根目录导入模块的能力。

## 验证边界

新增轻量测试覆盖延迟导出、可选后端初始化、优化异常/空输出回退，以及关闭回退时不重试。模型推理以 mock 替代，不是实际音频准确率、延时或 J6P 部署验证。部署 shell 通过语法检查。

下游指令解析仍只接收经过确认的英文文本：不能仅凭 `success=true` 判断可进入英文解析器，必须同时检查 `translation_success`、实际 `translation` 以及安全门结果。当前接口在翻译不可用时可能返回中文 `output_text`；不把中文回退当作英文翻译成功。

新 J6P 分支仅作为待验证实现保留，默认 x86 测试无需启动或配置它。不能根据本次代码整合宣称模型已转换成功、HBM 可运行、语音精度或平台指标达标。
