# 挑战赛道优化记录

## 依据与对比边界

以《初审评比方式及评分细则》为优先依据；原题目方案用于界定三类驾驶场景。基础版本代码参考 `basic-track-submission` 的 `2905058426c8d0c1f5d7a04accb8d802f328e673`，不把这个 Git 存档说成已与原提交压缩包逐字节一致。

比较分为同权重、同输入的组件对比，以及变更了场景设定的闭环复测。后者不作为同条件精度提升百分比。计时不包含独立提交的 ASR；编译器预估、x86 功能仿真、RTX 5090 实测和板端实测分别标识。

## 已实施的方法

1. 语言编码共享：解析与决策复用 ModernBERT backbone；相同语义指令命中缓存时不重复编码。
2. 决策与底线分离：原始模型提案、任务可执行性、风险限速、FSM 和最终物理控制分别记录。安全门阻断不当提案不计为模型预测正确。
3. 事件记忆：完成事实与目标位置轨迹分离；保持指令顺序，避免已经完成的事件因目标暂时不可见重新进入等待。
4. 观测闭环：使用同帧 RGB、相机位姿与 LiDAR 物体表面关联，去除同一物体不同类别的重复框。遮挡恢复同时约束外观、道路几何、运动边界与匹配唯一性；预测位置不具有完成权限。
5. 精确 CPU 算子：道路投影使用双精度 C 实现，保持原线段投影、等距首段优先和输出语义；关闭 fast-math 与浮点乘加重排，启动时编译，失败回退 NumPy。
6. 消除重复视觉推理：行人和超车观察器仅在同一帧、同一原始 RGB 对象及相同检测器输入条件下共享前视检测结果；不共享旧帧或低曝光灯色图像的结果。
7. 固定可用性结构优化：零兼容 BEV 输入用当前权重的真实恒定输出替代重复计算；真实 LiDAR 分支保留。该缓存为显式开关，训练、权重/缓冲区、设备和精度变化使缓存失效。
8. 混合量化与编译调度：BEV 卷积和投影/FFN 使用 INT8，敏感原始 RGB 编码与输出头保留浮点。已产生 ONNX、`.bc`、`.hbm` 和配对验证记录，不把未验证的量化分支替换默认闭环模型。

基础版已存在的可组合意图和时序监督属于保留与完善，不包装成首次提出。

## CPU 组件实测

数据为 12 组真实点云，包含约 2.2 万点和 43 个道路顶点；60 次配对测量。完整输出字典、选中点与证据逐值一致。

| 组件 | NumPy P95 | 编译 CPU P95 | 范围 |
|---|---:|---:|---|
| 通道证据计算 | 14.52 ms | 4.64 ms | 完整函数 |
| 物体表面筛选 | 18.87 ms | 1.65 ms | 完整函数 |
| 最近道路线段投影 | 17.48 ms | 3.70 ms | 投影内核 |

这不是全链路时延或 J6P 时延。第一次尝试的 NumPy 向量化实现反而更慢，未采用。

## 异构结构与编译器预估

CPU 负责同步、点云道路几何、实体关联、意图图、事件状态、规则和控制；x86 GPU 负责语言、视觉与神经决策。J6P 导出按 `nash-p` 指定 BPU 可支持神经算子，明确保留未支持算子的 CPU 回退，不声称存在实际 DSP 执行。

对同一 BEV 混合 INT8 `.bc` 调整编译调度：

| HBDK 编译器指标 | 初始调度 | 优化调度 |
|---|---:|---:|
| 单神经图预测时延 | 15.6234 ms | 9.3032 ms |
| 每次 DDR 访问预测 | 450.73 MB | 100.65 MB |
| 最小内存预测 | 71.55 MB | 57.07 MB |
| `.hbm` 文件大小 | 28,663,400 B | 25,185,920 B |

预测时延降低 40.45%，预测 DDR 访问降低 77.67%。优化参数为 `opt=2`、`balance=2`、单核编译。最大区间计算利用率预测为 62.1%，不是芯片平均异构利用率，不能直接作为评分细则的 80% 利用率证明。x86 SDK 功能推理的秒级计时也不是 BPU 性能。

固定输入的静态图已完成两组当前权重、96 组输入的数值对比，最大绝对差不超过 1.72e-5。支持算子的 FLOPs 计数约为原始 6.60549 G、零 BEV 0.58667 G、零相机/实时 LiDAR 4.11408 G、仅前视且零 BEV 0.241165 G；未覆盖的归一化、激活等算子明确排除。30%/40%/30% 分支占比假设下，计数比例约 28.67%，属于配置预测，不是实际分支频率，也不是全链路官方 FLOPs 结果。
