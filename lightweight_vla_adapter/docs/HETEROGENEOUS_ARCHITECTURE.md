# 挑战赛道异构处理与优化证据

## 实际处理结构

```text
文本指令 -> ModernBERT/可组合解析与术语规则 -> 意图图与共享语言特征
                                            |
同帧 RGB、点云/雷达、自车状态 -> 观测/预处理 -> 多模态 VLA 提案
                  |                         |
                  +-> 实体/道路/通道证据 ----+-> 任务可执行性、事件记忆
                                            |
                             独立物理底线与指令顺序约束
                                            |
                                     FSM / PID / CARLA
```

x86 实际分工：CPU 处理同步、点云与静态道路几何、意图图、实体关联、事件事实和执行状态；GPU 处理 ModernBERT、视觉检测、灯色模型、VLA 与训练过的时序模块。语言编码使用解析服务的同一 backbone；相同语义与指令缓存命中时不重新编码。它不是每帧重复调用两个完整语言模型，也不把语言缓存收益算成模型剪枝收益。

点云道路投影新增 CPU C 编译算子，使用双精度、关闭 fast-math 和浮点乘加重排，保持最近线段与等距时首段优先的定义。启动时编译/加载，不在决策帧编译；工具链不可用时保留 NumPy 原实现。12 组真实点云的完整通道证据和物体表面输出逐值一致。60 次配对测量中，通道证据 P95 从 14.52 ms 降至 4.64 ms，物体表面筛选从 18.87 ms 降至 1.65 ms；这是 CPU 组件测量，不是整链路或 BPU 时延。

J6P 导出分工：地平线编译器对固定形状神经图指定 `nash-p`，INT8 投影/FFN 与可支持算子由 BPU 编译；未支持的浮点算子保留明确 CPU 回退。CPU 继续负责非神经状态、物理证据、任务图与控制。没有伪造 DSP 上的执行或声称所有算子已迁至 BPU。

## 模型与输入边界

通用模型和递归事件模型分开标识。原始神经提案、风险参与、执行规则修正、最终物理控制分别记录；安全门拦住错误提案，不代表该原始提案正确。

相机视觉来自真实 RGB 编码。当前 `camera_bev` 是固定零兼容输入，不是相机抬升后的 BEV；场景二的 `lidar_bev` 来自真实点云处理，其余场景按已发布接口使用零兼容张量。不会将零张量写成观测到“没有障碍”。缺少观测仍受独立底线检查约束。

静态可用性优化只消去已知恒定输入的重复神经计算：使用当前冻结权重计算其真实恒定分支输出，而不是简单删除该输出。非零相机 BEV、形状/批量不匹配、非有限值或权重变化必须进入完整图或拒绝该 profile。真实点云分支始终保留实时计算。

## 编译器预估的含义

本次未结构压缩的混合 INT8 候选，HBDK 报告原始卷积操作数约 6.606 G，编译器预测模型时延 15.2 ms、最小模型内存约 75.73 MB、每次 DDR 访问约 443.88 MB。以上为单个神经图的编译器预估，不包含语言、检测、状态、控制、CARLA，也不是 J6P 板端时延或整链路内存。

BEV 卷积与投影/FFN 使用 INT8、原始 RGB 编码及敏感头保留浮点的候选，经同一 `.bc` 调度优化，编译预估从 15.6234 ms 降至 9.3032 ms（降低 40.45%），DDR 访问从 450.73 MB/次降至 100.65 MB/次（降低 77.67%）。优化使用 `nash-p`、`opt=2`、`balance=2`，`.hbm` 大小 25,185,920 字节，最小内存预估 57,065,088 字节。最大区间计算利用率预估为 62.1%，不是整芯片平均异构利用率，也不能据此声称达到 80%。该量化候选未替换默认闭环权重。

编译器包含 CPU 回退开销假设，其结果不能直接与 x86 功能仿真的秒级运行时间或 RTX 5090 微基准相减。异构利用率采用真实硬件监测或编译器明示的预估字段，并注明统计范围；“BPU 算子个数占比”“所有模块都有分工”和“峰值 TOPS”都不替代硬件利用率。

## 与基础版对比口径

基础版存档代码引用为 `basic-track-submission`，提交 `2905058426c8d0c1f5d7a04accb8d802f328e673`。实际提交材料中的旧日志优先于后来重跑数据；当前三场景若变更了触发位置、道路/限速或演员初始化，必须分开列出配置差异，不能称作同条件涨分。

功能优化记录：完成状态与目标轨迹分离、任务可执行性与风险速度解耦、风险恢复衔接、道路拓扑约束、真实实体的跨视角连续关联、同帧 RGB/点云验证、语义类别去重、递归事件与行为记忆。已有基础版的功能标为保留或完善，不重复包装成新发明。

结构和量化对比固定相同输入、权重来源和标签。核心分类准确率按独立标签计算相对衰减；配对输出一致率另列。动态缓存/事件触发收益按实际调用频率摊销，INT8 位宽缩减不写成 FLOPs 降低。以优势指标呈现结果，但同时保留未达标项和候选失败记录。

## 2026-10-09 精确 CPU 几何核接入

V101 将雷达支撑与平面判定合并为双精度 C 编译核，启动时构建，推理帧只执行已加载函数；禁用 fast-math 和浮点收缩，阈值附近和工具链不可用时回退 NumPy。日志 `geometry_backend.radar_ground_support` 记录实际后端、初始化耗时和错误。它不依赖某条路线或特定事件 ID，也不替代物理风险证据。

80 组同步物理雷达包、2869 个回波、320 对含支撑结构的 CPU 计时中，全部输出一致，P95 从 26.521 ms 降至 16.214 ms。phase-base 的恒定相机 BEV 专用化在另 40 组原生输入上输出误差为零，CPU 组件 P95 从 101.734 ms 降至 77.230 ms；该模型候选不含递归事件头，未据此宣称全模型或全链路精度。

本轮不增加或伪造硬件异构利用率。以上实测是 x86 CPU 组件证据；已有 `.hbm` 的 J6P 时延/内存/DDR 字段继续标为编译器预估，官方部署成绩与核心指标衰减按评分细则的环境和数据口径核验。
