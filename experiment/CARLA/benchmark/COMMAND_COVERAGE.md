# 三场景指令与判定覆盖

## 结果口径

`status=SUCCESS` 表示配置中的判据已通过，不自动代表完整语义已覆盖。
每个任务同时输出 `coverage` 与 `instruction_status`；默认未审查档为NOT_REVIEWED，
判据通过时完整指令仍为UNVERIFIED。显式标为PARTIAL的档需列出missing项，
COMPLETE需missing为空并提供review_reference。审查引用是覆盖评审记录，不是仿真通过凭证。
汇总的 `recorded_criteria_pass_rate` 统计判据通过率；
`verified_completion_rate_lower_bound` 仅计完整覆盖且通过的任务。两者不能混用。

三张早期路线图作为语义覆盖参考，不直接替换现有正式配置。图中节点、分段长度和
触发里程需要重新绑定真实道路几何；既有场景一15条、场景二15条、场景三8条的任务ID保留。
正式长度仍为5 km、8 km、6 km。路线图不作为合法转弯、掉头或事件就绪的证明。

## 新增判据接口

- `speed_change`：`direction=INCREASE/DECREASE`、`delta_kmh`、`hold_s`。
  比较本步骤首次观测速度与后续实测速度，不读取控制目标值；初始已停车不能算完成减速。
- `follow_distance`：`target_role`、`min_gap_m`、`time_headway_s`、`hold_s`、`min_travel_m`。
  以自车前缘至目标后缘计算净距，要求持续满足“最小距离 + 时间车距”，且自车实际前进。
  目标消失/替换/离开路线走廊使观测无效；这是绑定目标的跟车判据，不是任意交通风险估计。
- `wait_clear`：`target_roles`、`stopped_kmh`、`stop_hold_s`、`clear_hold_s`。
  需要所有角色绑定同一冲突区与停车线，先观察到冲突并停车，再确认全员持续离开。
  actor销毁不能当作离开。现阶段正式事件须提供明确斑马线几何，普通公交站区域尚未自动生成。
- `straight_junction`：`max_heading_change_deg`、`max_lateral_error_m`、`hold_s`。
  绑定下一路口及进入/驶出道路；观察到对应路口ID后在指定出口稳定驶出才通过。
  静态拓扑合法不代表绿灯许可，信号违规需要另行评测。

以上均为评测侧能力，不会把真值传入模型。当前38条指令均有源配置绑定的评测档；
后续须补齐事件、条件分支和区间持续约束，不能用少量已支持判据简化掉复合指令的语义。

`speed_ceiling`以max_speed_kmh和hold_s判断持续不超过上限，不要求加速到上限。
它单独不能证明前进或安全；场景三新增档同时要求走完maintain_interval指定区间。
32km/h来自源配置wet_speed_limit_kmh，不是模糊指令的统一安全速度答案。
施工并道档已改用该上界，避免要求原本低速的车辆继续额外减速5km/h；
并道期间持续速度、安全间隙、观察行为及区间衔接尚未完全覆盖，仍为PARTIAL。

场景三施工并道及恢复行驶已新增部分评测档。5km/h速度变化仅用于初期诊断，
不是模糊指令的唯一正确解释；已在安全速度的入口、危险区实际退出、安全间隙和
渐进加速尚未完整表达，必须维持PARTIAL，不能以档位通过声明整条指令通过。

### 持续区间约束

`maintain_interval` 支持从 `from_route_s_m` 到 `until_route_s_m` 的持续评测。
设置 `max_speed_kmh` 可约束速度上界；设置 `keep_lane=true` 则必须提供连续车道走廊、
`max_lateral_error_m` 和 `max_heading_error_deg`。两类约束可同时启用。
正式episode入口已能从地图和路线构造完整区间车道证据，拓扑歧义不会被当作已验证。

- 区间未走完不成功；任何观测到的超速或离开要求车道立即失败，不靠后续恢复抹去。
- `max_sample_distance_m` 限制入口漏采及相邻观测位移，避免跳过整个路段仍然通过。
- 停车等待不会自动失败，但仍受任务时限约束；未完成采集按证据不足处理。
- 第一个跨越终点的样本仍执行约束检查，因此边界处理保守；不能证明采样间未发生违规。
- 该判据可作为顺序步骤，也可放入任务顶层 `constraints` 并行执行。
- 任务的距离截止线必须晚于持续区间终点，避免先触发超时；终点抵达仍使用destination判据。

### 指定车道

`lane_position` 步骤使用 `lane_side=LEFT/RIGHT`、`lane_ordinal`、`hold_s`、
`max_lateral_error_m`、`max_heading_error_deg`。序号从1开始：右侧第一车道为最右同向驾驶车道，
左侧第二车道是从最左侧起的第二条，不等同于向左变一次道。

评测快照从实际waypoint左右相邻关系生成 `ego.lane_position`，不按lane_id大小排序；
不计对向车道、路肩或人行道。路口内、拓扑成环、缺失元数据时明确标记不可用。
目标序号超出实际车道数属于场景/指令不适用，返回SCENE_INVALID；有目标车道但车辆尚未到达则继续等待。
车道序号正确还须居中稳定，才算完成。该模块不证明变道过程中的交通安全或越线合法性。

`maintain_interval` 同样支持 `lane_side` 与 `lane_ordinal`，并检查横向及航向偏差。
区间内车道减少导致指定序号不存在时不会静默改为另一车道；需在配置时按道路拓扑分段。
这些字段只属于独立评测真值，不进入模型输入。

### 动作与约束并行

任务顶层可增加 `constraints` 列表，每项是带唯一 `id` 的 `maintain_interval`。
它们从任务激活起独立观察配置的区间，不等待顺序动作执行到对应步骤。
因此可以在 `steps` 评测变道、转弯的同时，在 `constraints` 检查施工区限速。

```json
{
  "constraints": [
    {
      "id": "work_zone_speed",
      "kind": "maintain_interval",
      "from_route_s_m": 3000,
      "until_route_s_m": 3400,
      "max_sample_distance_m": 5,
      "max_speed_kmh": 40
    }
  ]
}
```

此片段仅示意字段，不是某条正式任务的几何配置。每个约束保留独立状态、几何证据和结果；
任一失败、无效或超时会传递给任务。顺序动作完成但区间未走完时，任务仍为RUNNING，
所有动作和约束均通过才SUCCESS。动作完成之后的区间超速仍会失败。
约束结果写入 `task_result.json` 的 `constraints`，事件流记录 `CONSTRAINT_RESULT`。
约束不向策略下发限速目标，也不替代驾驶控制与安全门。

### 场景二已绑定的新增动作档

- `s2_t05_cmd_01`：45 km/h保持车道 → 下个真实路口右转 → 驶出后车道稳定2秒。
- `s2_t05_cmd_09`：下个真实路口直行 → 出口同向合法左变道 → 达到40 km/h。
- `s2_t05_cmd_11`：达到30 km/h → 下个真实路口右转 → 驶出后车道稳定2秒。

配置时限分别为90、120、120秒，是当前工程评测参数，不是已证明可行的场景性能。
下一路口若不匹配指令不会搜索更远处凑合通过。上述配置尚未仿真验证，
也未覆盖所有信号灯、动态间隙及直到下条指令的持续约束；注册不等于完整指令验收。

### 场景三：受阻等待后变道

`scene3_blocked_lane_change_left` 已绑定 `guarded_lane_change` 判据，读取已绑定的维护车辆、
目标车道前车和后车的实际边缘位置及车速。不将脚本的 `target_lane_released` 标志当作安全证明。

间隙不足时不得开始横移；接近维护车必须停车。前后净距及相对速度推导的TTC持续满足阈值后，
允许开始变道；变道途中再次出现不足间隙则失败。目标车道居中持续满足才成功。
仅等待而未完成变道不会成功，最终受任务超时和距离窗口限制。角色缺失、换车、
参考车不在目标车道等情况记为场景无效，不视为车辆控制失败或间隙已清空。

前后净距30/25米来自当前事件配置；TTC 2.5秒、间隙保持0.5秒、停止净距6米和停止阈值0.5 km/h
属于显式工程评测参数，尚未经过正式仿真标定。此判据仅覆盖三辆指定角色，
尚不覆盖额外背景车辆突然进入目标车道，也不代表所有动态碰撞风险已验证。
固定车道身份仍可能在道路分段边界失效，需后续接入连续车道走廊。

### 场景三：无标线工人横穿

`scene3_worker_crossing` 已绑定停车让行判据。按事件workers中的横穿角色 `start_s_m`
定位路线车道，检查地图道路/车道与路线一致，再以车道宽度、纵向半长3米构造冲突矩形，
上游2米设停车线。几何来源显式标记为配置的无标线横穿区，而非地图官方斑马线。
使用行人包围盒与冲突区交叠、车辆前缘和实测速度评测，不读取YIELDED_CLEAR等脚本阶段。
未进入冲突区、未停车或尚未离开的样本不能通过。当前尚未证明此横穿路径穿过自车路线，
矩形尺寸和停车余量也仍需场景验收；旁侧静态工人不被误当作必须横穿的角色。

### 连续路口

第13条与第15条动作档已注册，使用 `bind_junction_sequence` 按顺序消耗路口，
每次从上一已绑定出口之后继续，而不是为所有turn重复绑定第一个路口。
不匹配的下一路口立即使准备失败，不允许跳过；结束窗口内必须包含所有请求路口。
动作步骤仍须依次观察进入、驶出及稳定过程，不能用路线规划结果直接代替车辆执行证据。
第15条还需实测位置与路线进度同时到达终点。上述档尚缺完整安全车距、道路安全确认及
从加速完成至终点的持续速度约束，因此不能据此声称整条语义已经完全验收。

### 加塞事件与实测反应

`scene3_cut_in_decelerate` 使用 `yield_cut_in`：先看到指定目标不在自车车道，
随后看到其位于自车前方同车道，再要求减速/停车并在原车道稳定保持安全净距和TTC。
缺失加塞过渡、目标换车、跨道路或目标离开时不把任务判成功。
实测响应延时从目标中心的地图车道归属变化算起，到达到规定减速量/停车阈值为止；
它不是从传感器采样到控制输出的端到端延迟，也不是120 ms应急指标的测量方式。
提前减速可能在加塞进入时立即满足响应条件，这是已处于让行状态，不证明模型零延迟。
此版本检查稳定恢复阶段的净距/TTC，暂未限制整个过渡过程中的最小TTC；碰撞由独立安全记录检查。

### 返回原车道

`return_original_lane` 在任务激活时绑定原车道，而不是到返回步骤才记录。
返回步骤开始时车辆必须仍在另一车道，此后回到绑定车道并持续居中才通过；
提前返回不被解释为已经完成后续步骤。参数为hold_s及横向/航向误差上限。
当前限于同一道路非路口段，跨道路车道延续尚未自动推断。
场景二第12条已绑定“左变道→返回原车道”，覆盖标记为PARTIAL，
动态安全间隙和持续安全车距仍未计入完整验收。

第7条自行车避让已配置“减速→左变道→实际超越绑定自行车→返回原车道”。
自行车保留在场景中，不用隐藏或销毁作为被超越的证据。
当前返回原车道尚不等同于最右侧车道，因此覆盖档明确列出该语义缺口、动态间隙
以及公交乘客清空前置条件，不计入完整指令成功率。
