# 30秒目标历史与现有跟踪器的职责

## 实现结论

采用短时跟踪加30秒最后观测缓存，不把ByteTrack直接改成连续预测30秒。目标离开视野后，保存最后一次真实观测；超过最后真实观测时间30秒，且未再次被相同上游身份观测到时，在更新或查询时删除。处理暂停期间不启动后台线程，恢复处理或查询时先执行过期检查。

这项改动增加历史上下文，不等于增加当前目标检测准确率，也不等于实现跨ID、跨摄像头重识别。

## 与原方案比较

| 层次 | 原实现 | 本次改动 |
|---|---|---|
| 视觉连续跟踪 | `ByteTrackAdapter`使用supervision ByteTrack | 不修改原跟踪算法及短期预测缓冲 |
| 丢失缓冲 | 本机supervision 0.27.0.post2，默认lost_track_buffer=30，适配器frame_rate=10 | 保持约1秒的丢失缓冲，不误当成30秒 |
| 当前目标 | `PerceptionFrame.tracks`只输出当前跟踪结果 | 保持不变，不把历史目标拼回当前列表 |
| 历史上下文 | 无独立的30秒历史接口 | 新增`target_history`，历史状态标为`HISTORICAL` |
| 再次出现 | ByteTrack短时匹配 | 同一上游ID刷新最后出现时间；新ID不强制并入旧ID |

上述ByteTrack缓冲根据服务器实际安装版本源码核对：`max_time_lost = int(frame_rate / 30.0 * lost_track_buffer)`。在10Hz下对应10帧，约1秒。新缓存使用时间戳秒数，而不是帧数。

## 接口边界

- 实现在`core/target_history.py`，实时视觉管线和VLA物理雷达观测层共用同一实现。
- `CURRENT`表示本次时间戳下真实观测；`HISTORICAL`仅表示过去见过。
- `last_observation`保存最后测量时刻的观测快照（雷达为测量更新后的状态估计），不持续外推其坐标。
- 异步雷达使用测量时间写入、决策时间查询；即使真实回波比决策滞后0.1秒也会保存，但不能被标为决策时刻的实时实测。
- `last_seen_s`只由真实观测刷新。预测轨迹、重复查询和缺失帧不会续期。
- `expires_at_s = last_seen_s + 30`；恰好30秒仍保留，超过后删除。
- `usable_as_current_observation=false`的历史对象不能用于当前车距、TTC或可通行判定。
- 历史交通灯颜色、行人位置和车道占用同样不代表当前状态，不能用30秒保留替代它们的实时更新。
- 缺少时间戳时返回`UNAVAILABLE_TIMESTAMP`，不伪造30秒时钟。
- 同一目标被不同摄像头输出的相同数字ID，属于不同命名空间，不自动认定为同一个实体。
- 相机时间戳轻微乱序不会清空其他相机缓存；同源旧帧不刷新最新观测。
- 新场景调用`pipeline.reset()`；不允许把上一场景的ID当作新场景实体。
- 最大8192条缓存，达到上限明确报错，不悄悄提前遗忘尚在30秒期限内的目标。

示例历史条目：

```json
{
  "source": "carla:front",
  "track_id": "track_7",
  "last_seen_s": 10.0,
  "expires_at_s": 40.0,
  "age_s": 15.0,
  "status": "HISTORICAL",
  "usable_as_current_observation": false,
  "historical_position_extrapolated": false
}
```

该示例仅展示关键字段，完整输出还包含最后观测快照及身份依据。

## 使用

`RealtimePerceptionPipeline.process()`继续接收原有参数，传入递增的`timestamp_s`后自动输出`target_history`。原有`tracks`、道路结构及调用方式不变。严格JSON Schema已同步增加可选的历史字段。

```python
from scene_understanding.core.target_history import TargetHistory

history = TargetHistory(retention_s=30.0)
history.update("front", [{"track_id": "a", "category": "vehicle"}], 10.0)
past = history.update("front", [], 25.0)  # HISTORICAL，不是当前目标
expired = history.snapshot("front", 40.1)  # 已删除
```

历史可供语义模块理解“刚才那辆车”等引用，但当前对齐逻辑没有把历史目标自动当作已落地的实时对象。重新出现时若上游分配了新ID，保留两条不同记录；没有外观重识别证据时不强行合并。

## 与事件记忆的区别

目标历史保存“最后看到哪个对象、在什么时间、有什么观测”；事件记忆保存“跟车任务尚未完成、加速行为已被减速取代”。目标历史过期不自动取消用户的未完成指令。

事件记忆不复制整份目标坐标和速度快照，仅引用目标ID。引用的目标超过30秒未见时清除该引用，保留未完成事件；如观测层仍有最近见到的同一目标，则不因行为长时间未改变而错误删除引用。记忆不直接下发油门、制动或转向。

## 已完成测试

真实CARLA中从第5秒至第36秒连续屏蔽观测，共31秒。历史保留到第34.95秒，第35.00秒清空，符合最后观测约第4.95秒后的30秒保留要求。历史冒充实时观测计数为0，超期条目计数为0。重新观测后建立新轨迹，未强行声称跨越31秒仍完成身份重识别。

日志保存在VLA模块`outputs/observation_layer_v3/history_30s/`。这是一项故障注入测试，其23.125%的全时段关联覆盖率包含了31秒主动屏蔽，不能与正常观测覆盖率直接比较。

专项测试覆盖到期删除、同ID刷新、新ID不合并、相机命名空间、旧帧乱序、历史快照不可变、容量告警、缺少时间戳、Schema兼容，以及历史目标不进入当前`tracks`。

异步全链路联调曾发现“只缓存决策当前帧TRACKED状态”会漏掉滞后0.1秒的真实雷达测量。已改为只在新测量实际更新轨迹时写入测量时刻快照，并增加重复帧不续期、按测量时间到期的回归测试。初次联调的空历史记录保留，不作为缓存有效性证据。

本轮没有提交、推送或上传权重。

修复后两段25秒CARLA联调共1000个物理帧；250、245次决策中分别有247、243次实际输出历史条目，初始化确认前保持为空。未出现历史冒充实测、超期条目、观测错误或运行回退。记录位于`outputs/observation_layer_v3/async_integration/`；传感器到决策响应P95分别为52.17、53.34毫秒，不包含ASR或车辆物理执行时间。最终相关回归162项及28个子测试通过。
